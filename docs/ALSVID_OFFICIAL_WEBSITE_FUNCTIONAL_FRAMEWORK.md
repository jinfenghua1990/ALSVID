# ALSVID Official — 两家品牌共同功能框架

> 状态：实施基线 / 2026-10-22
> 对标：ADO E-Bike、Himiway
> 目的：先把用户共同需要的官网功能与页面结构固定下来，再逐项接通真实数据、业务流程和视觉细节。此文档是功能框架，不代表所有模块已实现或已上线。

## 1. 总原则

- 不重做 ALSVID 首页。首页继续采用 ALSVID 已确认的简洁、高级、Apple / DJI 风格；只接入统一导航、产品、配件、服务入口。
- 参考 ADO 与 Himiway 的共同功能：整车目录、车型详情、配件目录、购买路径、门店/经销商、试骑/咨询、订单查询、售后/保修、帮助内容、品牌与联系信息。
- ALSVID 首期采用自建商城与 Commerce；Shopify 不作为首期商品订单、登录或结账底座。支付仅由通过资格与验收的第三方 PSP 处理。
- 德国/奥地利为首期市场；德语和英语为核心公开语言。保留代码当前支持的其他 locale，所有新内容必须走共享词库。
- 产品层级是 Model ID → Variant → SKU；颜色切换更新同一 Model 下的 Variant/SKU，不创建重复 Model。
- 页面只展示有依据的商品、价格、库存、兼容、交付、网点、保修与服务事实。无数据时展示明确的“暂未开放/尚未配置”状态。
- 任何功能的“完成”需要代码、CI、精确生产发布及必要的浏览器/业务验收证据；路由或设计稿存在不等于闭环完成。

## 2. ADO 与 Himiway 的共同模块（目标信息架构）

| 模块 | 用户任务 | ALSVID 目标入口 | 最低可用功能 |
|---|---|---|---|
| 品牌首页 | 了解品牌、快速找产品 | `/{locale}` | 品牌主视觉、车型入口、技术/场景内容、服务入口；沿用现有首页设计 |
| 产品中心 | 浏览和筛选整车 | `/{locale}/bikes` | 平台/用途分类、产品卡、型号筛选、可核实规格、详情入口 |
| 商品详情 | 判断是否适合自己 | `/{locale}/explore/{slug}` | 图片/视频、颜色/版本、规格、使用场景、包装/交付说明、FAQ、配件/服务入口 |
| 产品比较 | 比较不同车型 | 产品中心内比较区 | 只比较有审核来源的同一类规格；移动端可读；数据不齐时不伪造 |
| 配件中心 | 找到适用配件 | 产品中心内 `#accessories` | 配件分类、搜索/筛选、配件详情、车型适配信息 |
| 购物袋/购买 | 检查所选商品 | `/{locale}/cart` → `/{locale}/checkout` | 型号/颜色/SKU、数量、移除、合计与明确的预览/正式购买状态 |
| 经销商/服务网点 | 找附近销售或服务点 | `/{locale}/dealers`、`/{locale}/service-locations` | 国家/地区/城市筛选、已核实联系方式、服务范围、导航入口 |
| 试骑/咨询 | 预约体验或联系销售 | 产品详情/经销商页面 | 车型与地点选择、联系方式、请求提交、确认状态；未接入后端时不得显示预约成功 |
| 订单查询 | 查找购买后的订单状态 | 官网服务入口 / My ALSVID | 身份验证、只查看当前用户有权访问的订单、状态与更新时间；未接通时标明暂未开放 |
| 售后/保修/维修 | 获取使用和维修支持 | `/after-sales`、My ALSVID | 保修政策、维修/售后申请、案件状态、车型/VIN 关联、维修配件入口 |
| 帮助与说明书 | 自助解决常见问题 | 官网帮助/车主中心 | FAQ、产品说明书、组装/维护/安全信息、联系支持；只发布已审核资料 |
| 关于我们/联系 | 了解公司并找到支持 | 品牌内容页/页脚 | 品牌介绍、联系方式、合法信息、经核实的合作与支持入口 |
| 账户/车主中心 | 管理个人车辆和服务 | `/{locale}/login`、My ALSVID | 安全登录、车辆/VIN、订单、保修、售后、说明书和配件；数据必须经过真实身份/所有权授权 |

### 不作为首期强制项

- 真实客户评价/评分：只有有来源、获授权的真实评价才展示。
- 促销、优惠券、会员积分、分期等：需要明确商业政策与业务实现后再排期。
- 在线聊天、AI 导购：属于增强功能，不得阻塞核心目录/服务框架。
- ADO/Himiway 各自特有的保修年限、折扣、免费配送或送达承诺：不可照搬。

## 4. 建议的页面框架与导航

### 公共 Header
1. ALSVID Logo → 首页
2. 产品（整车与配件同一入口）
3. 技术/品牌（有审核内容后显示）
4. 经销商/试骑
5. 车主服务
6. 语言切换（保留共享 locale 规则）
7. 购物袋数量（只反映当前预览/实际购物袋的真实状态）
8. 登录/车主中心入口

桌面端维持清晰的一行导航；滚动时采用统一、稳定的置顶行为。移动端使用简洁菜单，保证产品、配件、服务和购物袋容易到达。首页 KV 不强行塞入额外按钮或改变已确认构图。

### 公共 Footer
- 产品与配件
- 试骑/经销商/服务网点
- 车主服务/说明书/FAQ/售后
- 联系我们/关于 ALSVID
- 法律与消费者信息（只有核实后的内容才发布）
- 语言入口与版权信息

### 产品列表模板
- 页面标题与简短说明
- 顶部车型/平台分类
- 桌面侧边型号索引（沿用现有实现，不重复制造两套导航）
- 筛选/排序（只使用真实字段）
- 商品卡与产品比较
- 配件区及车型适配筛选
- 空状态、加载状态、错误状态
- 手机端筛选抽屉/横向分类与清晰返回路径

### 商品详情模板
- 图片/视频与颜色选择
- Model / Variant / SKU 的可视化选择关系
- 已审核的卖点与规格
- 包装内容、交付与售后信息（有核实数据才显示）
- 配件/兼容配件
- FAQ/说明书/试骑或咨询入口
- 加入购物袋/立即购买：依据真实购买能力显示，不允许预览态伪装成订单

### 公共服务模板
- 清楚的页面标题、适用对象与操作步骤
- 车型/地区/订单/VIN 输入仅在具备对应后端和安全授权时开放
- 真实提交、成功、失败、处理中状态
- 联系支持的备用路径
- 德语/英语文案、移动端和可访问性验收

## 5. 共用组件与数据职责

共用 UI 组件建议集中复用：
- `SiteHeader` / `SiteFooter` / `LocaleSwitcher`
- `ProductModelNavigator` / `ProductFilter` / `ProductCard` / `ProductCompare`
- `ProductGallery` / `VariantSkuSelector` / `CompatibilityList`
- `CartSummary` / `CartLineItem` / `PurchaseStateNotice`
- `DealerLocator` / `TestRideRequest`
- `SupportEntryCards` / `FAQList` / `ManualDownload`
- 通用加载、空状态、错误状态、表单校验、成功/失败反馈

以上是逻辑组件建议；实现前先查找并复用现有组件，不为命名而重复造组件。

数据真源与边界：
- Product / Variant / SKU / 发布状态：ALSVID Product/Engineering 权威数据；公共站只读已批准发布的公开字段。
- 价格/税费/运费/订单/付款：ALSVID Commerce 与经批准 PSP；未核实则不开放真实购买。
- 库存与库存移动：Inventory 权威数据；不能从“已发布”推断“有货”。
- 配件兼容：已审核 Model/Variant/SKU/BOM revision 与选配规则；不能凭图片或名称推断。
- Dealer/Service 网点：已核实 Partner/地点数据；没有真实数据不编造门店。
- Vehicle/VIN/所有权/保修/售后：Vehicle/Service/Identity 权威数据；UI fixtures 不等于真实记录。
- 图片/视频/说明书：经批准的资产与内容来源；二进制对象存储，数据库保存元数据/关联。
- 所有页面使用共享 i18n 词库；不在页面里硬编码仅英文文本。

## 7. Definition of Done

单个模块只有同时满足以下条件才可标记完成：
1. 页面与路由真实可用，导航可到达，刷新/直接访问/返回正常。
2. 使用真实且有授权的数据源，或明确标示尚未配置的诚实空状态。
3. 德语/英语与响应式布局通过检查。
4. 加载、空数据、错误、未授权与成功路径都已检查。
5. 相关测试/CI 通过，改动已合并并发布到正确的 Production commit。
6. 必要的浏览器/业务操作已实际验证；记录证据和遗留问题。

## 用户确认的分工（2026-10-16）

用户明确将官网、My ALSVID、Dealer Portal、消费者商品详情页、购物袋页面的连贯设计、前端交互与超级链接整合交给 Penpot 对话负责。此次说明取代此前“只负责消费者首页”的理解。Admin 工作台和内部模块继续由 Ardot 工作流负责；修改共享组件时必须保留其现有行为。

对外页面可以采用 Figma 或 Penpot，每页只登记一个已确认设计源。原官网首页采用 Penpot 文件 `9e056cfe-f83f-81f8-8008-cc4972e16647`、页面 `86ab18b0-fcc4-8052-8008-cc5c73d58530`。其余页面的最终 Penpot 设计源尚待登记，代码存在不代表设计已经完成。

这是前端与体验整合分工，不改变业务数据写入权威：ALSVID Commerce 承担首期自建 B2C 交易编排，获批 PSP 负责支付，ALSVID 承担车辆和服务事实，WMS 承担仓储执行。任何未来外部渠道接入都需单独批准，并遵循 ADR 0005、DATA_OWNERSHIP.md 和现有权限规则。

## 目标访问链路

1. **消费者：** 官网 → 平台/产品目录 → 实际商品详情 → 规格选择 → 本地预览购物袋 →（通过 ADR 0005 发布门禁后）ALSVID Commerce 结账编排 → 获批 PSP → 实际订单确认。
2. **车主：** 官网服务入口 → My 登录 → 原本要访问的授权车辆/服务页 → 手册、保修、维修记录 → 服务申请 → 实际结果与返回路径。
3. **经销商：** 官网经销商入口 → Dealer 登录 → 授权目录 → Dealer/B2B 采购与订单协作 → 订单状态 → 交付车辆、售后、配件与文件；首期不默认依赖 Shopify B2B。

保留登录前的安全返回目标；邮箱相同或内部角色可进入预览，不等于具备车辆归属或企业资源权限。经销商合作申请与登录是不同动作，不把普通登录页标成已经可提交的合作申请。

## 实施顺序与验收

1. 登记页面、唯一设计源、语言覆盖、入口/出口、登录要求、数据权威和真实接入状态。
2. 统一对外导航：Logo/首页、产品、购物袋、车主账户、经销商入口、语言切换、面包屑及返回/继续浏览。消费者页面不套用 Admin 工作台模板。
3. 建立商品详情与购物袋设计及路由；验证 Shopify 接入方式、商品标识、价格与库存后再启用交易。未接入时明确显示状态，不做假订单或假成功提示。
4. 沿用受保护路由，逐步整合 My、Dealer 的页面结构，再通过授权 API 替换 fixture/空状态。
5. 遵循 ALSVID_WEB_I18N_STANDARD.md：中文、德文、英文使用翻译 Key；图片与文字分离；语言切换保留当前页面、查询参数和区块。
6. 对每个可点击外观实际验收：点击结果、目标内容、刷新、浏览器返回、键盘焦点、登录返回和错误恢复。禁止死链接、无关跳转，以及用说明弹窗冒充完整购物流程。
7. 按设计确认、代码、CI、Production、业务验收分别登记证据；遵循现有 PR → CI → 精确 main CI → Production → 线上验收流程。

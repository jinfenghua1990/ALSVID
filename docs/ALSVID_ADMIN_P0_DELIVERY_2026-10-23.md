# ALSVID Admin P0 核心业务交付清单（2026-10-23）

> 负责人指定本轮优先设计和落地 P0：产品中心、订单中心、库存仓储、生产管理、系统设置。
>
> 本文记录 P0 业务闭环和验收条件，**不是声称全部完成**。Admin 顶部保留独立“订单管理”导航；订单中心仍由 Commerce/B2C 与 Dealer/B2B 共同提供入口，不新增重复订单表或订单事实。

## 1. 交付目标与实际边界

P0 不是五个展示页面，而是五组能够读取、写入、校验、回溯的真实运营能力。各业务事实各归唯一领域主档：

| P0 业务模块 | 唯一权威领域 | 内部 Admin 入口 | 已存在的能力基础 | 尚须完成的业务验收/接入 |
| --- | --- | --- | --- | --- |
| 产品中心 | Product / Engineering | \`/admin/product\` | 型号、配置/SKU、BOM、首页商品绑定、公开目录审批流程 | 主商品→Variant→SKU 一致性；发布版 BOM 锁定；配件适配、双语内容与实际审核操作验收 |
| 订单中心 | Commerce | \`/admin/ecommerce/orders\` | 自建商城内部订单草稿、价格版本；原有订单查询 \`/admin/orders\` | 公开结账、外部 PSP 支付事实核验、取消退款、库存预占、订单履约；B2B 不混入 B2C 单据 |
| 库存仓储 | Inventory / Warehouse / Logistics | \`/admin/inventory\` | 实际库存流水/预留、仓库、库位、盘点、供应商仓配置 | 服务端 ATP 市场/仓库/预留规则、并发防超卖、WMS 沙箱、差异重试与对账 |
| 生产管理 | Production / Engineering | \`/admin/production\` | 生产计划/工单、质量检查、装配与 VIN 信息 | 锁定 BOM 版本、缺料/生产状态授权、车辆唯一追溯与订单交付关联的端到端验收 |
| 系统设置 | Identity / Audit / Platform | \`/admin/settings\` | 员工与审计记录、管理门户会话保护、部分系统集成配置 | 角色/动作/组织/数据范围矩阵；邮箱登录/密码策略；关键操作审计；集成健康与失败恢复 |

管理台的 P0 中心接入以上领域的**现有授权 GET API**，不创建新的产品、订单、库存、生产或员工数据事实。

## 2. P0 中心首批交付（本 PR）

- 位于 \`/admin\` 工作台顶部，展示五个可选择模块及直接跳转现有业务工作区的入口；保持 13 个一级导航正常。
- 使用 \`GET /v1/product/catalog\`、\`/v1/commerce/storefront/summary\`、\`/v1/inventory\`、\`/v1/production\`、\`/v1/auth/users\`、\`/v1/audit?limit=100\` 查询真实授权数据。
- 只显示 API 返回的记录条目数，来源和读取时间明确；这些数字**不代表**销量、在售数量、应收金额、实时 WMS 库存或已付订单。
- 登录过期、权限不足、接口失败、格式错误、尚在读取与真实零条各自显示不同状态。
- 部分来源不可用不影响其它来源；可手动刷新，取消上一轮未完成的请求。
- P0 业务门禁显示为「待开发」「待外部条件」「待业务验收」，不会将 API 可读写与全流程生产验收划等号。
- 原有业务数据摘要保留在可折叠区域；新 P0 中心不复制数据表、代替领域 API 或提供绕过审计的快捷写入。
- 界面采用桌面 5 列选择卡片 + 双栏详情，平板/手机自适应；保持与 Admin 统一顶栏/导航。

## 3. 下一批必须完成的 P0 功能与最小验收

### 产品

- [ ] 产品 ID 唯一且与 Variant/SKU 关联，选择颜色只能切换 SKU，不创建另一个商品主 ID。
- [ ] BOM Revision / Build Specification 发布后在已启动生产工单上锁定；版本升级保留原始工单的技术快照。
- [ ] Product 发布到 WWW 的审批链：有权限的新建、提交、批准、撤回及审计，实际操作截图留证。
- [ ] SKU 配件适配、图像/资料、DE/EN 文案与价格前置校验；未审核不得公开购买。

### 订单

- [ ] B2C 店铺 DE/AT EUR 真实订单：行项目 SKU、价格/税/运费快照、地址和幂等创建；与历史渠道单严格区分。
- [ ] PSP 收款校验：可信 Webhook、签名、重放保护、金额/币种/订单绑定、退款处理、对账；无 PSP 凭证时结账禁用。
- [ ] 订单提交前服务端 ATP 校验、库存原子预留、失败回滚、取消/超时释放；库存未知一律不可售。
- [ ] 订单发运、签收、VIN 配置交接、财务结算与售后关联；每个状态转换有身份权限与审计。

### 库存仓储

- [ ] SKU 数量库存与 VIN 单台车辆库存分离、仓库市场资格和有效预留规则可核对。
- [ ] 并发出库/预留防超卖，库存动作可追溯订单/采购/生产/工单来源。
- [ ] 采购收货、退货、调拨、盘点差异触发可信库存流水而非直接覆盖余额。
- [ ] 第一家 3PL/WMS 的 API 文档、凭据和沙箱连接；映射、错误重试、差异对账、回执验收。没有授权则不能声称接通。

### 生产

- [ ] 生产计划/工单创建、发布、启动、暂停/异常、质检、完成各阶段权限及事件可追溯。
- [ ] 产品发布版 BOM、工单装配物料、缺料和不合格品隔离绑定唯一 Revision。
- [ ] VIN/车架号唯一性与归属：关联真实工单、批次、质量签核和车辆实际交付，不可静默重写。
- [ ] 从授权订单到生产、入库、出库和车辆交付至少完成一条真实测试环境场景。

### 系统设置

- [ ] 员工/角色/动作权限/组织范围矩阵；管理员与经销商、车主、供应商账户跨门户越权验证。
- [ ] 密码与邮箱验证码登录开关、密码重置、首次登录、会话续期和登出流程按已决策策略验收。
- [ ] 关键订单、库存、生产、发布、退款和权限变更均包含操作者、时间、前后状态与审计证据。
- [ ] 第三方接口、任务队列、邮件/通知健康状态来源可信，有最后成功时间/错误原因及受控重试。

## 4. PR / 发布验收要求

每一个 P0 业务闭环需记录：唯一业务领域、API 路由、读写权限、校验规则、版本/幂等或事务、防重复/越权、失败恢复、审计、数据库迁移（若有）、单元与集成测试、PR、主干 CI、部署 SHA、实际登录后浏览器操作结果。

- 未经真实业务验收，不把「待业务验收」改为「已完成」。
- 新上线风险较高的 PSP、仓库集成、所有权、资金和库存写入应按正式变更流程单独审查；严禁依靠视觉按钮展示成功。
- 无第三方账户/签署合同/API 沙箱时，只交付可验证的安全禁用状态与配置准备，不编造外部能力。

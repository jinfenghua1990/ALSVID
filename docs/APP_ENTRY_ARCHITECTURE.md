# ALSVID 独立项目入口与应用切换器规范

> 状态：2026-10-14 已确认的命名与目标架构。本文记录产品规范，不代表四个独立前端、SSO 联登、域名或应用切换器已经全部实现或上线。

## 四个独立项目

| 正式项目名称 | 中文定位 | 面向用户的名称 | 职责 |
| --- | --- | --- | --- |
| ALSVID Official | ALSVID 官网 | ALSVID / ALSVID 官网 | 品牌、产品、内容及自建商城体验；支付由获批 PSP 执行 |
| My ALSVID | 车主中心 | My ALSVID；车辆资产区域可使用“我的车库” | 用户车辆、归属、保修、维修与车辆生命周期 |
| ALSVID Dealer Portal | 经销商平台 | ALSVID Dealer Portal / 经销商平台 | 经销商 B2B 采购、交付与售后协作 |
| ALSVID Admin | 内部运营中心 | ALSVID Admin / 内部运营中心 | 公司内部业务管理、运营与权限管理 |

四者是独立前端项目，各有用户体验、路由、权限边界和迭代流程，不是同一系统中的四个页面，也不是 Admin 的四个业务模块。独立项目可以共用 monorepo、设计系统、统一 API 和基础设施，无需因此拆分为四套后端或数据库；后端仍遵循现有模块化单体及数据权威规则。

## 项目之间的关系

- 大部分入口关系是跳转到另一独立应用；只有需要协作的身份与业务事实通过统一身份认证、授权 API 和部分数据联动连接。
- My 使用 ALSVID 自有邮箱验证与独立车主会话；员工、车主、经销商身份仍按各自授权验证。未来外部渠道身份映射须经批准并单独验证，不能假设所有门户共用同一种登录。进入目标项目仍检查角色、组织、车辆范围和权限，员工身份不自动获得车主或经销商权益。
- 公开官网无需登录即可浏览；需要身份的功能接入 ALSVID 自有认证。My 不以 Shopify Customer OAuth 为前提；任何未来外部渠道身份映射都需按独立集成规范验证。
- 车辆、客户、经销商、保修、售后等仅共享各项目履行业务所需的事实；ALSVID Commerce 是自建 WWW B2C 订单权威，获批 PSP 是支付处理权威，WMS 是仓储执行权威，不复制完整外部数据库。
- 开发在本地、CI 临时运行，均与 Production 数据/凭据隔离；共享云端 Development 已退役。地址沿用 [PORTAL_DOMAINS.md](PORTAL_DOMAINS.md)，名称变化不触发资源或域名迁移。

## Admin 顶部右侧应用切换器

在 Admin 顶部右侧定义 **应用切换器（App Switcher）**，按钮建议显示 `ALSVID Apps`。展开后使用下列入口：

| 入口显示 | 目标项目 | 辅助说明 |
| --- | --- | --- |
| 官网 | ALSVID Official | 打开品牌官网与商城 |
| 车主中心 | My ALSVID | 打开车主车辆与服务中心 |
| 经销商平台 | ALSVID Dealer Portal | 打开经销商业务平台 |

点击入口在新标签打开对应环境的独立应用，保留当前 Admin 页面与操作状态。跨应用跳转不作为 Admin 内部路由切换，也不替代人员/角色切换或权限检查。目标项目未配置或未上线时，应标明“待配置”或“规划中”，不提供虚假可用链接。

Admin 内对 My ALSVID 的入口使用“车主中心”；“我的车库”用于消费者自己的车辆资产区域，避免让员工误认为正在查看自己的车辆。Admin 自身无需在此菜单重复提供入口；需要显示当前应用时可标识 `ALSVID Admin`。

## Supplier Portal 预留 — 2026-10-16

Supplier Portal 是已确认的后续外部供应商门户目标（#185），分阶段交付，不改变当前四个核心项目。它面向 ALSVID 上游供应商，最终 UI 归 Figma；Admin 内部供应商管理和采购流程归 Ardot。当前可复用 `apps/web` 与统一 API，不按门户数量强拆后端。

Supplier Portal 当前不加入 Admin 顶部 App Switcher 的默认入口。只有在供应商门户实际配置、部署并完成权限验收后，才增加面向相应身份的入口。不得因为架构预留而展示虚假的可用链接。

## 命名与实施影响

本次确认将正式官网项目名从 `ALSVID WWW` 更新为 **ALSVID Official**，中文使用 **ALSVID 官网**。`www` 继续作为域名子域及既有资源技术标识，已存在的服务名、包名、环境变量和部署标识不因文档改名自动变更。

正式项目名称与入口显示名称分开维护：项目名保持上表一致，入口文案按用户身份和场景选择。命名权威见 [SYSTEM_NAMING.md](SYSTEM_NAMING.md)，Admin 信息架构见 [ALSVID_ADMIN_IA.md](ALSVID_ADMIN_IA.md)，统一认证边界见 [SSO_AND_PORTAL_ARCHITECTURE.md](SSO_AND_PORTAL_ARCHITECTURE.md)。

本次交付仅更新文档。四前端拆分、域名绑定、跨应用联登和 App Switcher UI 的实际完成状态应由代码、CI 与部署验收证明；不得根据本文把相关能力标记为已完成。

# ALSVID Admin IA 规范

状态：已确认，作为 Admin 信息架构基准  
范围：内部 ALSVID Admin；不适用于官网、商城、Shopify 前台、Dealer Portal 或 My ALSVID。

## 1. 固定定位

ALSVID Admin 是 **ALSVID 公司内部运营中枢**。

固定一级模块：

```
工作台
产品
订单
生产
库存
经销商
客户
售后
供应链
数据
设置
```

这里处理后台 UI、业务流程、权限、员工、产品/BOM、VIN、生产、库存、订单、售后和数据分析。

**不讨论官网商城视觉，不把 Admin 做成传统 ERP，也不把业务页做成营销官网 Hero。**

## 2. 固定交互骨架

Admin 采用“顶部一级导航 + 当前模块左侧二级导航”的现代化 SaaS 后台结构：

```
┌─────────────────────────────────────────────────────────────┐
│ ALSVID  工作台 产品 订单 生产 库存 经销商 客户 售后 ...    │
├──────────────┬──────────────────────────────────────────────┤
│ 当前模块     │                                              │
│ 二级导航     │                页面工作区                    │
│              │                                              │
└──────────────┴──────────────────────────────────────────────┘
```

规则：

- 一级导航始终位于顶部，不使用永久固定的传统左侧一级菜单。
- 工作台首页保持全宽，不额外显示左侧二级导航。
- 点击“产品 / 订单 / 生产 / 库存 / 经销商 / 客户 / 售后 / 供应链 / 数据 / 设置”后，在左侧出现该模块的二级导航。
- 左侧只显示当前一级模块的子功能，不混入其他模块。
- 移动端将一级和二级导航收纳为菜单。
- 当前一级模块与当前二级页面都必须有明确 active 状态。
- 顶部一级导航 hover 时提供模块用途说明，帮助员工快速理解边界。

## 3. 一级模块

| 模块 | 路径 | 目标 |
| --- | --- | --- |
| 工作台 | `/admin` | 运营总览、待办、异常与关键指标 |
| 产品 | `/product` | 平台、型号、SKU、BOM、零件与工程资料 |
| 订单 | `/commerce` | B2C / B2B 订单、售后配件订单、履约与异常对账 |
| 生产 | `/production` | 计划、工单、装配、质检、VIN 与出厂追溯 |
| 库存 | `/inventory` | 成品、半成品、零件、仓库、调拨与预警 |
| 经销商 | `/dealers` | 经销商档案、区域、授权与经营关系 |
| 客户 | `/customers` | 客户档案、车辆绑定、购买与服务记录 |
| 售后 | `/after-sales` | VIN、保修、维修、配件申请与服务记录 |
| 供应链 | `/supply` | 供应商、采购、来料检测、评价与成本 |
| 数据 | `/overview` | 销售、生产、库存、售后与经销商分析 |
| 设置 | `/settings/environment` | 员工、权限、安全、审计、通信、集成与环境 |

## 5. 工作台首页原则

工作台不再承担完整菜单功能，重点回答“今天公司发生什么、我需要处理什么”。

建议固定为：

```
运营概览
├─ 今日订单
├─ 生产状态
├─ 库存状态
├─ 售后待处理
└─ 经销商动态

待办与异常
├─ 待审批
├─ 生产异常
├─ 库存预警
└─ 售后工单

数据区
├─ 订单趋势
├─ 生产进度
├─ 库存概况
└─ 关键运营分析
```

没有真实数据时保持空态，不填充模拟业务数字。

## 6. UI 视觉原则

- Admin 是业务工作区，核心业务页采用紧凑标题和高信息密度，不使用官网式大标题或营销 Hero。
- 工作台可保留品牌感较强的欢迎区，但不能挤占业务信息。
- 顶部一级导航简洁稳定；左侧二级导航承担当前模块的业务定位。
- 产品、订单、生产、库存、经销商、客户、售后、供应链、数据、设置使用同一套字体、间距、卡片、表格、表单和空状态语言。
- 支持 Light / Dark 两套主题。

## 7. 业务边界

- Admin 是内部运营后台，不替代 Shopify 的商城前台体验。
- Dealer Portal 是经销商自己的业务视角；Admin 是公司员工管理经销商和内部业务的视角。
- My ALSVID 是消费者购买后的车主生命周期入口；Admin 负责内部查看与处理对应 Vehicle / VIN 业务事实。
- 产品、车辆、VIN、生产、客户与售后形成完整生命周期闭环。
- 官网商城视觉、产品营销页面、Shopify Theme 不属于本项目范围。

## 8. 实现约束

- 一级和二级导航数据集中维护于 `apps/web/app/app-navigation.ts`。
- 共享 `AppShell` 负责顶部一级导航、当前模块左侧二级导航以及移动端收纳。
- 工作台 `/admin` 不显示桌面左侧二级导航；其他一级模块进入后显示左侧上下文导航。
- 页面通过 `navigationFor(activeHref)` 标记当前入口；存在相同落地路径时，以具体二级入口作为 active 项。
- 未实现入口可以保留结构位置，但必须标注“骨架”，不得伪造业务数据。
- 新增或调整一级模块，必须同步更新本规范与导航数据。

## 9. 独立项目应用切换器

Admin 定位为内部运营中心。顶部右侧的应用切换器（App Switcher）按钮建议使用 `ALSVID Apps`，入口显示“官网、车主中心、经销商平台”，对应 ALSVID Official、My ALSVID、ALSVID Dealer Portal。

这些目标是独立前端项目，使用对应环境的地址在新标签打开，保留 Admin 操作状态。跨应用共享统一身份认证和部分数据，目标应用仍独立验证权限。消费者自己的车辆区域可以使用“我的车库”，内部员工入口使用“车主中心”。未配置或未上线的项目须明确标注状态。完整规范见 [APP_ENTRY_ARCHITECTURE.md](APP_ENTRY_ARCHITECTURE.md)；本节不代表切换器已实现。

## 10. 导航与日常环境规则

左侧菜单按业务主题分组并默认展开，桌面端在顶部下方保持可见，长菜单独立滚动。存在共用页面地址时，跨页面链接使用 `nav` 参数保留当前一级模块，刷新后也不能切换到别的模块。

日常业务使用 ALSVID Production。测试页面和日常测试入口关闭使用；ALSVID Development 继续保留为发布前的独立验证环境，数据、文件和凭据不迁入正式环境。

## 11. 收尾阶段：保留优先原则（2026-10-14 确认）

- 除非明确提出删除某项功能、按钮、导航、页面或入口，否则不得擅自移除或隐藏。
- 已有但未接入的搜索、通知等入口必须保留；可标注待接入或保持禁用状态，不能因尚未实现而删除。
- 收尾优先修复布局、字体、视觉一致性、导航激活、跳转、空状态及明显错误，不扩大业务范围。
- 对确实需要删除的内容，先取得明确确认；清理无用代码也不得破坏既有入口和预留接口。
- 所有变更通过独立分支与 PR 审查，验证后再合并和发布；不得将提交 PR 视为已经上线。

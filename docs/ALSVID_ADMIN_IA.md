# ALSVID Admin IA 规范

状态：已确认，作为 Admin 信息架构基准  
范围：内部 ALSVID Admin；不适用于官网、商城、Shopify 前台或客户公开门户。

## 1. 交互骨架

Admin 采用现代化 SaaS 后台结构：

```
顶部固定区域：ALSVID 品牌｜一级导航｜搜索 / 通知 / 账户
页面区域：当前模块的二级导航｜工作区内容
```

一级导航常驻顶部。点击模块后，仅展开该模块的二级导航；不使用永久固定的传统左侧一级菜单。二级导航位于模块上下文区域，移动端收纳为菜单。

首页工作台不堆叠业务菜单，聚焦今日运营概览、实时状态、待办、异常与关键业务数据。

## 2. 一级模块

| 模块 | 路径 | 目标 |
| --- | --- | --- |
| 工作台 | `/admin` | 运营总览、待办、异常与关键指标 |
| 产品 | `/product` | 平台、型号、SKU、BOM、零件与工程资料 |
| 订单 | `/commerce` | 外部订单事实、销售订单与履约状态 |
| 生产 | `/production` | 计划、工单、装配、质检、VIN 与出厂追溯 |
| 库存 | `/inventory` | 成品、半成品、零件、仓库、调拨与预警 |
| 经销商 | `/dealers` | 经销商档案、区域、授权与经营关系 |
| 客户 | `/customers` | 客户档案、车辆绑定、购买与服务记录 |
| 售后 | `/after-sales` | VIN、保修、维修、配件申请与服务记录 |
| 供应链 | `/supply` | 供应商、采购、来料检测、评价与成本 |
| 数据 | `/overview` | 销售、生产、库存、售后与经销商分析 |
| 设置 | `/settings` | 用户、权限、审计、集成与环境 |

## 3. 二级导航规则

- 二级导航只显示当前一级模块的内容，按业务主题分组。
- 当前页面在一级和二级导航中都显示 active 状态。
- 未实现入口可以保留结构位置，但必须标注“骨架”，不得伪造业务数据。
- 页面空状态要说明真实数据接入状态与刷新规则。
- 车辆全生命周期是生产、客户与售后共用的业务对象，不单独形成一级导航。

## 4. 业务边界

- Admin 是内部运营后台，不替代 Shopify 订单权威或 WMS 仓库执行权威。
- Admin 只保存和展示履行 Vehicle 360、客户/经销商、保修、售后与对账所需的业务事实。
- 官网与商城视觉、导航和购物流程保持现状，本次 IA 调整不得修改这些页面。
- 产品、车辆、VIN、生产、客户与售后形成生命周期闭环。

## 5. 实现约束

- 一级导航数据集中维护于 `apps/web/app/app-navigation.ts`。
- 共享 `AppShell` 负责顶部一级导航、当前模块二级导航和移动端收纳。
- 页面通过 `navigationFor(activeHref)` 标记当前入口。
- 新增模块必须先更新本规范与导航数据，再实现页面能力。

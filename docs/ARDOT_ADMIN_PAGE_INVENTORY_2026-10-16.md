## 1. 设计工具归属

- **Ardot：** ALSVID Admin 全部内部运营页面，包括工作台及下列十个业务模块。经销商采购流程可以在 Ardot 作为内部流程原型讨论。
- **Figma：** 所有对外门户的最终 UI：ALSVID Official / Shop、My ALSVID、ALSVID Dealer Portal，以及未来 Supplier Portal。
- **本地现有仓库：** 日常代码修改主位置；**GitHub：** 同步后的架构与协作记录、审查、CI 和发布入口。
- Ardot 中的“官方首页”“我的车库”“经销商入口”只能作为跨应用入口，不代表对应消费者/外部门户页面归 Ardot 设计。
- Ardot 与 Figma 不得同时维护同一页面的两份最终设计稿。Dealer Portal 最终 UI 不归 Ardot；Admin 的供应商管理和内部采购仍归 Ardot。

## 2. Ardot 页面清单

### 2.1 工作台

- 工作台总览（Admin 唯一首页）
- 经营 KPI、待办、异常与内部模块快捷入口
- “工作台”和“经营驾驶舱”是同一页面职责；合并重复画板，不建设两个后台首页
- 不包含消费者商城 Hero、购物车或消费者账户导航

### 2.2 产品中心

- 产品总览
- 产品平台管理
- 型号、配置 / Variant、SKU 管理
- BOM 与零件库
- 工程文件、版本控制与发布状态
- 产品生命周期：开发中、量产、停产、归档
- 型号详情及产品追踪

### 2.3 订单中心

- 订单总览、订单详情、新建订单
- B2C、Dealer B2B、配件 / 售后订单的内部运营视图
- 外部渠道 / Shopify 订单映射
- 库存预留、生产需求关联
- 发货、物流、交付及 VIN 绑定状态
- Admin 不重建 Shopify checkout 或通用 OMS；商业订单权威遵循 Shopify / 相应外部渠道边界

### 2.4 生产中心

- 生产总览
- 生产计划、排产与产线视图
- 工单列表、工序详情、进度与异常
- 来料检验、装配质检、出厂检测
- BOM、零件批次追溯
- VIN 管理、车辆档案、待入库交接

### 2.5 库存中心

- 库存总览与详情
- 原材料、零件、半成品、整车的分层视图
- 仓库、库位与库存调拨
- 逐 VIN 库存状态和预留来源
- 库存移动台账、盘点与差异
- 库存预警、周转及呆滞分析
- 明确 ALSVID 库存台账与 WMS 仓储执行的职责边界

### 2.6 经销商中心（内部员工视角）

- 经销商总览与内部档案详情
- 区域、门店、授权与合作协议
- 采购预测、B2B 订单内部管理
- 经销商库存、终端销售表现与目标达成
- 售后能力、培训认证、合作状态
- Ardot 可展示内部采购流程原型；经销商对外 Portal 的最终页面由 Figma 设计

### 2.7 客户 / 车主中心（内部员工视角）

- 客户总览与客户详情
- 企业客户、车队客户
- 车辆资产、VIN 绑定状态、所有权历史
- 购买、交付和经销商来源
- 保修、维修、保养、配件及售后履历
- 客户请求、隐私处理与审计相关页面

### 2.8 售后中心

- 售后总览
- 保修管理
- 售后 / 维修工单列表与详情
- 服务网络、工单分派及状态时间线
- 维修项目、换件、费用与服务报告
- 配件申请 / 更换，以及替换件履约关联

### 2.9 供应链中心

- 供应链总览
- 采购需求、采购流程与采购订单（PO）
- 供应商档案与详情
- 供货关系、零件供应关系
- 收货、来料质检、交期与异常
- 替代料、多来源供应、质量与成本趋势
- 供应商管理和内部采购审批属于 Admin
- 不把 Admin 页面直接公开给供应商；未来 Supplier Portal 是独立对外门户，由 Figma 设计并按阶段交付

### 2.10 数据中心

- 经营看板
- 销售、生产、库存、供应链、渠道及售后分析
- 报表、筛选、指标下钻与导出
- 数据更新时间、缺失状态与访问权限提示

### 2.11 设置中心

- 设置总览
- 组织、员工、角色与数据权限
- 登录安全、审计、第三方集成、消息与 API
- 仓库 / 产线 / 库位、区域 / 渠道、业务字典与编号规则
- 保修政策、通知模板等主数据配置
- 密钥只显示配置状态，不回显密钥值

## 3. Admin 页面通用设计规则

- 一级导航固定为：工作台、产品、订单、生产、库存、经销商、客户、售后、供应链、数据、设置。
- 工作台首页全宽显示，不出现模块左侧二级导航。
- 进入业务模块后保留顶部一级导航；左侧仅显示当前模块的二级导航，右侧为页面工作区。
- 各模块与业务页面采用独立画板 / 页面，便于逐页讨论、评审和修改；不要将多个模块挤进同一个设计画板。
- Admin 优先效率、信息密度、操作路径和状态可读性；表格、筛选、抽屉、表单、批量操作优先。
- 覆盖加载、空数据、无权限、过期缓存、部分同步失败、重试和最后成功同步时间等状态。
- 示例数据必须标记为演示数据；不要将 fixture 表现成真实客户、订单、库存、销量或 SLA。
- 窄屏下表格需退化为可读布局；检查键盘焦点、对比度、语义标签和触控目标。
- Ardot 画板、GitHub 路由、所属领域、数据来源和实现状态应可追溯。
- 页面存在不代表真实 API、权限、审批、发货或交易能力已完成；验收按设计、代码、CI、部署、业务验收分别记录。

## 4. Figma 对外门户范围（与 Ardot Admin 画板分开）

以下页面的最终 UI 归 Figma，不属于 Ardot Admin 页面清单：

1. **ALSVID Official / Shop：** 官网与消费者商城；消费者商品交易、购物车、结账、支付、退款及商业订单遵循 Shopify 边界。
2. **My ALSVID：** 车主车辆资产、VIN、保修、服务、维修、文件、配件及售后体验。
3. **ALSVID Dealer Portal：** 经销商对外采购、订单、交付、库存及服务协同；采购交易与 Shopify B2B 的边界按 GitHub 架构执行。
4. **Supplier Portal（未来）：** 上游供应商自助履约门户，分阶段建设；供应商登录、PO 确认、交期、进度、发货通知和文件等需要独立权限与组织范围。

上述门户可以共享品牌基础规范，但不能共用 Admin 页面模板，也不能把内部工作台暴露给外部用户。WMS 继续负责仓储执行。

## 5. 可直接转发给 Figma 的说明

请按 GitHub 最新架构边界整理 ALSVID 设计：

- Figma 负责 Official / Shop、My ALSVID、Dealer Portal 的最终 UI，并为未来 Supplier Portal 预留独立设计范围。
- Ardot 负责 Admin 内部工作台及产品、订单、生产、库存、经销商（内部视角）、客户 / 车主（内部视角）、售后、供应链、数据、设置十个模块。
- 请把各个门户、模块和业务页面拆成便于独立评审与修改的画板 / 页面；不要把多个独立页面挤在一个画板里。
- 不要把 Admin 工作台、内部表格、侧栏或待办复制到消费者 / Dealer / Supplier 门户；也不要将 Figma 外部门户最终稿放回 Ardot 作为第二份最终设计。
- Ardot 中的经销商采购只作内部流程原型；Dealer Portal 最终 UI 在 Figma。
- 官方首页和 My ALSVID 车主体验在 Figma；Ardot 里的同名项目若存在，只作为跨应用入口，不作为设计源。
- Supplier Portal 是未来独立外部门户，不是已完成/已上线页面；不直接公开 Admin 供应商管理或采购页面。
- 请在交付时逐项登记 Figma 文件 / 页面链接、页面清单、设计状态和待确认项；设计稿完成不等于代码、集成或业务验收完成。

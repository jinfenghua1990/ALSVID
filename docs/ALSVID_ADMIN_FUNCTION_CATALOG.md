# ALSVID Admin 全量功能目录与分模块交付基线

- 状态：全量规划基线（2026-10-23）；不是上线状态证明。
- 适用范围：ALSVID 内部运营后台 Admin。
- 配套文档：[Admin 信息架构](ALSVID_ADMIN_IA.md)、[数据权威边界](DATA_OWNERSHIP.md)、[业务流程](BUSINESS_FLOWS.md)。
- 原则：先列全量范围，再逐模块开发、测试和验收；不得因为功能出现在目录或导航中，就声称已实现。

## 1. 总体结构

当前 13 个一级导航作为稳定的业务入口。完整功能通过模块内的二级导航、工作区标签、详情页和流程页面承载；“订单管理”只提供跨渠道查询与履约导航，不创建独立订单事实。

| 一级模块 | 功能范围 |
| --- | --- |
| 工作台 | 跨模块待办、异常、全局搜索、审批与快捷入口 |
| 产品研发 | 产品主数据、型号/SKU、BOM、工程资料、技术版本、产品生命周期 |
| 电商 | 自建 B2C 商城、商品发布、市场定价、可售库存、购物车/结账、订单、促销、退换货 |
| 经销商/B2B | 经销商准入、组织与权限、报价、B2B 采购订单、配货、交付、试骑网点 |
| 生产制造 | 需求计划、生产计划/工单、装配、质检、VIN 出生、追溯 |
| 仓储物流 | 库存台账、仓库库位、收发存、调拨盘点、拣配发运、WMS |
| 供应链采购 | 供应商/工厂、询报价、采购订单、供应商交期、收货、来料质量、供应商绩效 |
| 客户车主 | 客户档案、车辆/VIN 归属、车主生命周期、购买/交付/服务历史 |
| 售后服务 | 保修、服务申请、维修工单、配件申请、服务网点、SLA 与服务历史 |
| 财务结算 | 应收应付、发票/单据、支付凭证、退款、核销、对账、汇率和到岸成本 |
| 数据分析 | 销售、生产、库存、采购、交付、客户、售后和财务分析 |
| 设置 | 身份与权限、审计、邮件/通知、集成、文件、系统健康和配置 |

## 2. 工作台与通用运营能力

- 今日概览：订单、采购、生产、库存、物流、售后和财务待办；只显示有真实数据来源的指标。
- 待办中心：待审核、待确认、待收货、待质检、待发货、待付款/对账、待售后处理。
- 异常中心：库存差异、同步失败、订单支付异常、生产延期、交付延期、邮件失败、数据校验失败。
- 全局搜索：按订单号、商品 ID、SKU、VIN/车架号、客户、经销商、供应商、采购单、工单、运单和发票号查找。
- 跨模块详情跳转：显示关联记录与来源，不复制或另建业务事实。
- 任务与审批：指派负责人、截止时间、优先级、状态、备注、附件、审批记录和逾期提醒。
- 通知中心：站内通知与邮件发送记录；显示发送结果和失败原因。
- 批量操作：仅为已实现且有权限的操作提供批量选择、确认和结果摘要。
- 数据导入/导出：模板、字段校验、预览、错误行报告、权限校验和操作审计。
- 快捷创建：在有权限的前提下，从关联页面创建采购申请、售后工单等，不绕过所属领域规则。

## 3. 产品研发

### 3.1 产品主数据
- 产品类型：整车、配件、维修零件及后续批准的类型。
- 技术平台：FC / CT / FT / GT 等平台。
- 型号、版本、Variant、颜色、规格、市场适用范围、状态。
- SKU、条码、产品 ID、图片/媒体、产品分类和属性。
- 型号与首页展示位、商城商品、价格、库存的关联查看。
- 产品生命周期：草稿、评审、技术发布、停产/停售、替代型号。

### 3.2 工程与版本
- BOM、BOM Revision、零件清单、替代件、用量与单位。
- Build Specification、装配要求、扭矩/检查规范、技术说明。
- 工程图、CAD/3D/爆炸图、说明书、认证和合规附件。
- 工程变更申请、评审、影响分析、生效日期和历史版本。
- 发布版本锁定；已用于生产的 BOM/规格不得被静默覆盖。
- 零件与供应商来源、采购规格、批次/序列号追溯关系。
- 产品成本估算和技术资料下载权限。

## 4. 电商（ALSVID 自建 B2C）

### 4.1 商品目录与内容
- 商品目录、分类、系列、筛选属性、商品排序。
- 型号/Variant/SKU 选择；同一商品详情页切换颜色或配置。
- 商品审核、发布、下架、停售和发布失败原因。
- 官网首页商品绑定、展示顺序、场景/内容模块引用和预览。
- 商品详情内容、图片/视频、技术参数、说明书、常见问题。
- 德语/英语文案、德国/奥地利市场可见性、URL/SEO 元数据。
- 商品修改预览、发布记录、操作者和回滚/重新发布策略。

### 4.2 市场、价格与库存资格
- DE / AT 市场售价、EUR 货币、价格生效期和价格历史。
- 税费、运费、折扣与最终应付金额的展示规则；正式规则须经过税务/法律审核。
- SKU 库存、VIN 实体车库存分开展示。
- 服务端可售库存（ATP）规则：商品发布状态、市场、仓库履约范围、已预留量、渠道分配、库存新鲜度和缺货策略。
- 预约登记（仅邮箱）、付费预订、预计交付时间、取消/退款规则和通知。
- 缺货、预售、停售、不可配送、库存未知等明确状态。
- 库存查询失败不得默认为零库存或可售；库存台账可用量不得直接等同商城可售量。

### 4.3 购物与订单
- 购物车、SKU/数量校验、购物车持久化与价格重新校验。
- 结账信息、收货地址、配送选项、税费/运费、订单确认页。
- 订单草稿、提交幂等、订单状态机、订单详情和状态历史。
- 订单邮件、客户可见订单状态、发货与物流跟踪链接。
- 取消、退货/撤回申请、退款申请、换货/补发关联。
- B2C 订单搜索、筛选、导出和订单关联车辆/VIN 的只读跳转。
- 异常订单：支付待确认、重复提交、付款失败、地址异常、履约失败。

### 4.4 支付、促销与商城设置
- PSP 配置引用、支付尝试、支付结果验证、退款、对账与回调事件记录。
- 金额/币种/订单绑定校验、签名验证、幂等和重放保护。
- 优惠码/优惠券、活动规则、有效期、适用 SKU/市场、使用限制和审计。
- 运费规则、配送区域、退货地址、消费者条款、隐私说明和联系信息。
- 支付服务未选择、未配置或未通过验收前，真实收款与结账必须保持禁用；不得仅凭浏览器跳转显示“已付款”。

## 5. 经销商 / B2B

- 经销商申请、资料上传、审核、拒绝原因、补充资料和准入状态。
- Partner/企业主档、经销商组织成员、邀请、角色、停用与权限审计。
- 国家/区域、授权等级、经营范围、门店/服务网点、联系方式。
- B2B 产品目录、经销商专属价、阶梯价、报价、有效期和价格历史。
- 采购询价、报价确认、B2B 订单、订单行、交期、订单变更与取消。
- 付款条款、预付款/尾款状态的只读展示；财务事实由 Finance 管理。
- 库存可供货信息、订单配货/预留、直发工厂或德国仓发货路线。
- 发货、运单、交付确认、经销商收货、车辆交接和 VIN 清单。
- 试骑申请、试骑预约、网点、试骑车辆与结果记录。
- 经销商文件资料、产品培训、营销素材、售后/保修申请、配件申请。
- 经销商门户只可访问本组织授权的数据；不能依靠邮箱相同推断组织权限。
- B2B 订单流程未实现前，只显示明确的建设状态，不伪造可提交订单入口。

## 6. 生产制造与质量

- 需求汇总、生产预测、补货建议、产能与生产周期计划。
- 生产计划、工单、工单优先级、排期、目标/实际开始与完成时间。
- 工单关联已发布的 Build Specification 与锁定的 BOM Revision。
- 物料需求、零件分配、缺料预警、领料与退料记录。
- 工序/装配步骤、操作人员、检查清单、工时和异常备注。
- 来料检验、过程检验、终检、测试结果、照片/附件和签核。
- 不合格品、隔离、返工、报废、偏差放行与纠正措施。
- VIN/车架号出生、唯一性校验、序列化部件、生产批次与生产记录。
- 车辆配置、实际装配零件、软件/固件（若适用）、出厂检验与放行。
- 成品入库、工单完工、生产成本归集和生产延期原因。
- 供应商/零件批次到整车 VIN 的正向追溯，以及 VIN 到零件/批次的反向追溯。
- 销售订单不等于生产工单；生产状态只能由授权的生产流程更新。

## 7. 仓储、库存与 WMS

- 仓库主数据、库位/货架、国家、时区、仓库状态与可履约范围。
- 库存流水：入库、出库、预留、释放、调拨、盘点差异、冻结、报废和退货。
- SKU/零件库存与 VIN 实体车辆库存分开；不得将两者相加。
- 收货、验收、上架、移库、拣货、复核、包装、发运、退货入库。
- 批次、序列号、库位、可用/预留/冻结/待检数量及更新时间。
- 循环盘点、全盘、差异审批、盘点任务与历史记录。
- 库存预警、安全库存、缺货风险、滞销/长期库存和库存准确率。
- 库存预留、超时释放、订单取消释放和并发防超卖规则。
- 第三方 WMS/3PL：服务商配置、凭据引用、连接验证、仓库/SKU 映射、库存快照、事件回执、同步任务、失败重试和对账。
- 外部库存快照不得直接覆盖内部流水；必须记录来源、时间、差异和核验状态。
- 没有真实服务商文档、商户账号和沙箱验收时，不显示“已连接/同步成功”，不将外部库存纳入可售量。

## 8. 供应链采购与供应商

- 供应商/工厂档案、联系人、能力、国家、交期、币种、付款条件和资质文件。
- 采购需求、询价单、供应商报价、比价、批准与采购建议。
- 采购订单、订单行、版本、价格、交期、预付款和供应商确认。
- 供应商交期承诺、进度报告、延期预警、变更申请与跟进记录。
- 采购物料/成品到货通知、收货计划、收货数量与剩余未交数量。
- 分批收货、短收/超收、损坏、拒收、待检和供应商退货。
- 来料质量、检验报告、供应商纠正措施和质量评分。
- 采购单、收货记录、供应商发票和 Finance 应付义务的匹配。
- 采购成本、价格变化、交付及时率、质量不良率和供应商绩效。
- 供应商自助门户按已确认的分阶段方案建设；供应商身份和经销商身份权限分离。

## 9. 物流、出口与交付

- 出货计划、运输方案、承运商、货代报价、预计/实际费用和运输时效。
- 工厂直发经销商、工厂发德国仓、德国仓发经销商等不同履约路线。
- 装箱单、商业发票、商品/零件明细、箱号、重量、尺寸和货值。
- HS 编码、原产地、出口申报、进口清关、关税/进口 VAT 和费用凭证。
- 电池及危险品运输所需文件和承运条件（按实际产品与运输方式审核）。
- 订舱、提货、离港、在途、到港、清关、派送、签收等里程碑。
- 运单号、追踪链接、交付证明、异常/延误、丢损和索赔记录。
- 运费、保险、关税等到岸成本分配给相关采购/商品/车辆的规则。
- 退货、补发、返修运输和逆向物流。
- 计划日期与实际日期分开保存；不得用计划完成日期冒充已交付。

## 10. 客户、车主与车辆生命周期

- 客户/Partner 主档、个人/企业类型、联系方式、地址和语言偏好。
- 客户重复记录识别、合并审批、联系历史和资料修改审计。
- 营销同意、隐私同意、退订/抑制名单和法律依据分开管理。
- 客户订单、预约、支付摘要、交付/物流、售后和服务历史的授权关联视图。
- Vehicle/VIN 搜索、整车配置、生产记录、出厂检查、仓储/交付状态。
- 车辆交付、车主认领、VIN/购买证明核验、所有权开始/结束记录。
- 所有权转移保留历史，不覆盖前任车主的历史记录。
- My ALSVID 账户关联状态、车辆车库和服务状态（Admin 仅管理授权关联）。
- 车辆注册/保修起始日期、保修状态、召回/安全通知（如适用）。
- 客户数据导出、更正、删除/限制处理请求及合规审计。
- 不得仅凭邮箱匹配自动认定车辆所有权；客户资料不得越权暴露给经销商。

## 11. 售后服务与维修

- 售后申请入口、来源、客户/经销商、订单、VIN、购买/交付证明。
- 工单分类、优先级、状态、负责人、SLA、截止时间和升级规则。
- 保修资格、保修条款版本、保修期计算、审核证据、批准/拒绝原因。
- 故障描述、诊断步骤、照片/视频、故障码（如适用）和维修方案。
- 维修工单、服务网点/技师、工时、零件、操作步骤、复检与关闭。
- 配件申请、库存查询、预留/领用、发货、补发和退回记录。
- RMA/退货、换新、维修后回寄、运单和交付确认。
- 费用承担方：保修、客户付费、经销商承担或供应商质量索赔。
- 客户通知、工单时间线、客户反馈、满意度和重复故障分析。
- 维修/配件消耗要通过所属库存与财务流程登记，不能直接改库存数字。
- 服务记录关联 VIN 并进入车辆服务历史；关闭工单不能删除历史证据。

## 12. 财务结算

- 应收、应付、财务单据、付款义务、收款/付款、分摊、余额和结清状态。
- B2C 销售、经销商应收、供应商应付、物流费用和售后费用的来源关联。
- PSP 支付尝试、核验状态、退款、拒付/争议、手续费和结算批次。
- 发票、贷项通知单、付款凭证、供应商发票、收据和附件。
- 银行/PSP 对账单导入、自动匹配建议、人工核对、差异和复核记录。
- 预付款、定金、部分付款、多笔分摊、汇款费用和未核销余额。
- EUR 及其他业务所需币种、汇率来源、汇率日期、汇兑差异。
- 德国/奥地利税务与 VAT 配置、税务证据和报表导出（上线前由专业顾问审核）。
- 运费、保险、关税、进口费用和其他到岸成本的分摊。
- 产品/订单/渠道毛利、费用构成、现金流和期间汇总。
- 月结/期间锁定、调整记录、审批、审计导出。
- Finance 保存财务事实；订单金额快照、支付成功、发票、应收应付和银行结算不是同一状态。

## 13. 数据分析与报表

- B2C/B2B 销售额、订单量、转化、取消、退款和客单价。
- 按市场、型号、Variant/SKU、渠道、经销商、时间段分析。
- 库存准确率、可售量、缺货、周转、库龄、预留和盘点差异。
- 采购成本、供应商交期、来料质量和采购履约率。
- 生产计划达成率、工单周期、缺料、返工和质量问题。
- 物流准时率、运输时长、清关异常和到岸成本。
- 客户/车主增长、车辆激活、保修覆盖、服务工单 SLA 和重复故障。
- 财务应收应付、收款周期、退款、支付费率、毛利和现金流。
- 指标定义、统计口径、更新时间、数据来源、筛选、下钻和导出。
- 所有报表受角色权限约束；接口失败、权限不足和无数据必须区分，不得用假数字填充。

## 14. 设置、集成与平台运维

- 员工/内部身份、登录策略、角色、权限、会话、邀请、账号停用。
- 按模块、动作、组织和数据范围授权；所有写入在服务端重新校验权限。
- 登录/密码重置/邮箱验证码策略、邮件模板、发送日志、失败重试和限流。
- 业务通知模板、语言、接收规则、站内通知与邮件送达状态。
- 集成配置、服务商账号引用、连接状态、能力、映射、同步运行和错误摘要。
- 密钥只保存 Secret Manager 引用，不把真实密钥返回前端或写入公开仓库。
- 定时任务、worker/outbox、失败任务、重试、幂等键和运行时间。
- 安全/业务审计日志、操作者、对象、时间、结果和变更前后摘要。
- 语言与地区配置、国家/货币/时区、商品文案和邮件文案。

- 运行配置、功能开关、Webhook 注册与投递记录、API 客户端权限。

## 15. 跨模块支撑能力（不能遗漏）

以下能力横跨多个一级模块，但需要有明确的唯一负责人和统一交互：

- **营销与内容**：线索、活动、内容素材、官网落地页、SEO、归因、邮件营销、同意/退订。营销同意与抑制名单归 Marketing 权威管理；交易性订单通知与营销发送分开。
- **质量与合规**：供应商来料质量、生产质检、产品技术合规、售后故障/召回、文档版本和审计证据。可从生产、采购、售后入口进入，但不能把质量记录当普通备注。
- **文件与资产**：产品图片/视频、工程图、证书、合同、发票、维修照片、出货文件统一使用资产元数据与对象存储；按业务权限控制，不重复存储业务事实。
- **工作流与审批**：报价/价格发布、采购下单、收货差异、质量放行、退款、财务核销、经销商准入等按风险设置审批；不允许通用审批绕过领域权限。
- **通信与客户互动**：邮件线程、模板、发送状态、客服记录和附件；AI 可以生成摘要/草稿，敏感或对外动作按策略需要人工确认。
- **主数据治理**：重复记录、编码规则、数据导入校验、停用/合并流程、来源和变更历史。
- **安全与审计**：权限拒绝、登录事件、关键状态变更、支付/库存/车辆所有权等不可静默修改的证据。

这些横向能力可以在 UI 中归属相关一级模块或「设置」，但底层必须使用明确的业务领域和数据写入权威。

## 16. 与外部门户的边界

Admin 是内部员工运营中枢，不等于把所有用户操作都放进 Admin：

- **ALSVID WWW / 自建商城**：面向公众展示产品、内容、预约和 B2C 购买；Admin 管理内容、商品发布、价格规则和交易运营。
- **Dealer Portal**：经销商自己申请、采购、查单、查看交付/可供货信息、提交售后与配件申请；Admin 负责内部审核和运营。
- **My ALSVID**：车主查看订单/车辆/VIN/保修/服务记录并发起申请；Admin 负责客户、车辆和售后后台处理。
- **Supplier Portal**：按已确认阶段逐步开放供应商确认采购订单、交期、发货资料和发票证据；Admin/Procurement 负责审核与业务授权。
- **Service**：若作为独立服务入口存在，其外部申请界面与 Admin 内部工单处理界面分开。

门户可以引用相同业务记录，但身份权限、页面体验和写入权威必须分开。

## 17. 状态标注与验收规则

每个功能在实际开发任务中必须有明确状态：

- **已有且验收**：代码、CI、必要的权限测试和实际运行证据齐全。
- **部分接入**：已有部分页面/API，但闭环、权限或异常恢复尚未完成。
- **待开发**：仅在功能目录/需求中列出，没有可用的真实业务流程。
- **外部前置**：等待 PSP、仓商、承运商等官方 API、商户账号、凭据或沙箱。
- **不适用/延期**：经负责人确认暂不进入当前阶段。

不得把页面、菜单、设计稿、数据库表、测试样例或配置记录单独当成“功能完成”。真实交易、资金、库存、车辆归属等关键能力需要服务端业务规则、权限与审计、失败恢复、自动测试和必要的端到端验收。

## 18. 推荐交付顺序

1. **全局底座**：统一导航/权限/错误状态、全局搜索、任务与通知、审计基础。
2. **产品研发 + 电商**：唯一商品主数据、发布/价格、ATP、预约/结账/支付门禁、B2C 订单。
3. **采购 + 生产 + 仓储 + 物流**：从供应商订单到车辆出生、入库/发运、德国/奥地利交付的完整追溯。
4. **经销商/B2B**：准入、价格、采购、付款条件、库存分配和交付。
5. **客户车主 + 售后**：VIN 归属、保修、维修、配件、客户通知和车辆历史。
6. **财务结算**：应收应付、支付/退款核验、对账、发票、税务与到岸成本。
7. **数据分析 + 平台治理**：真实报表、集成健康、质量/合规、主数据治理和自动化告警。

可以并行开发不共享写入权威的任务，但每个业务模块都必须独立验收。不要一次性生成大量“建设中”空页面代替实施；全量目录负责不遗漏，模块开发负责把每项能力做成真实可用流程。

## 19. 不属于 ALSVID Admin 的范围

- CoffeeBear 国内经营系统、1688、吉客云及国内电商/税务流程。
- 用 Admin 替代第三方 PSP 执行支付或替代 WMS 执行物理仓储操作。
- 将 ALSVID 建成通用多平台 OMS，或在没有明确决策时复制外部渠道完整数据库。
- 复制产品、SKU、订单、客户、库存、车辆、付款或会计记录来让页面看起来完整。

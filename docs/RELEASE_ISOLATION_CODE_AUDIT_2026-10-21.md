- 2026-10-21 08:36（北京时间）`ALSVID WWW Production Deploy` [#39522375229](https://github.com/jinfenghua1990/ALSVID/actions/runs/39522375229) 完成成功。它仅证明 Web 的发布验证成功，不证明 API 或邮件已更新。

## 本次已发现且提交修复的代码问题

1. **预约 API 部署配置遗漏：** 全栈部署步骤拼接了 `FC1_RESERVATION_EMAIL`，但原步骤未将 GitHub 的 `NEXT_PUBLIC_FC1_RESERVATION_EMAIL` 变量注入 step env，导致 API 的预约收件地址可能为空。修复为显式传入变量；未配置时仍返回 503，不假装预约成功。
2. **预约邮件 HTML 注入：** 以前将用户输入的型号、颜色、邮箱直接拼接到 HTML 通知。修复为集中标准化和 HTML 转义；邮件主题不再拼接个人邮箱。
3. **预约服务异常输入：** 之前字段不是字符串或 body 为空可能造成 500。修复为确定性的 400 输入校验。
4. **前端预约接口防护：** 增加来源检查、大小限制、JSON 校验及上游不可达时返回 503，避免误报成功。
5. **回归测试：** 增加不合法输入、长度限制、HTML 转义的自动测试，由现有 CI 执行。

## 已覆盖的排查范围

- GitHub Actions: CI、PR 自动合并、WWW-only 发布、正式全栈发布；分支保护必需检查。
- Web: 登录会话 Cookie 作用域、受保护门户会话、公开预约接口及发布版本验证。
- API: 全局身份认证 Guard、邮箱验证码入口、预约通知链路、主要运行时依赖。
- Identity: 验证码的 TTL、重试限制、错误投递回收与内部/客户身份边界（基于代码路径检查）。
- CI 原有全栈检查：工作流 actionlint、架构检查、类型检查、测试、构建以及 Docker/数据库烟测。

**这不是对全部 878 个仓库文件逐行人工安全审计。** 本次修复重点集中在已发现的故障链与高风险输入边界；其他业务领域需持续以 CI、集成测试和真实环境烟测验证。
